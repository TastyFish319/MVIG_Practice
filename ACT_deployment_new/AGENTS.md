# AGENTS.md — ACT_deployment_new 开发约定

本文件是本工程的最高开发约定。所有后续开发（人或 AI）都遵循这里的规则。

## 1. 目标

在 I2RT YAM 双臂（从臂 follower）上部署 LeRobot ACT 策略，完成**推理 + 真机执行**，形式为**完整、自包含的工程文件夹**：
整个 `ACT_deployment_new/` 拷到 `mvig-ubuntu` 上即可运行（权重放进 `checkpoints/`）。

| 要求 | 说明 |
|---|---|
| 正确推理 | 加载 `pretrained_model/`（config + safetensors + processor），输入输出按 checkpoint 内的契约文件解析 |
| 速度历史 | v3 模型需要右臂"前 100 ms 的关节速度"，开局历史不足时补零（与训练 `first_two_zero` 一致） |
| 时延 | 模型预热、首次推理、推理提前量、超时与过期处理都要考虑 |
| 平滑 | 时间插值 + 分块提交/交叉淡化 + 限速限加速；初始化/回零用五次多项式轨迹 |
| 交互 | 一键脚本：选任务 → 选权重 → 选模式 → 实时状态面板 + 单键控制 |
| 安全 | 急停、紧急回零、故障保持、主程序崩溃后的救援脚本 |
| 可扩展 | 多任务注册表；模型输入输出改变时只改契约解析层；左臂将来可能也要动 |

## 2. 机器与环境

| 机器 | 用途 | 规则 |
|---|---|---|
| 本机 Windows | 开发 + 离线验证（`sim` 模式，CPU） | 无硬件 |
| `mvig-ubuntu`（ssh 别名） | 真机运行 | **默认连不上**；除非用户明确说能连，否则不要尝试 ssh |

运行时复用部署主机上**已有的两个环境**，不新建、不往里装包：

| 角色 | 解释器（相对 SI 仓库根 `R`） | 用途 |
|---|---|---|
| 设备环境 | `R/.venv/bin/python`（Py3.10，有 i2rt / portal / pyrealsense2 / cv2 / yaml） | 控制台、机械臂 worker、相机、控制循环 |
| 模型环境 | `R/.superinference/local/act-inference-py312/bin/python`（Py3.12，torch cu128 + lerobot 0.4.4） | 模型服务进程 |

路径可在 `local.env` 里覆盖（见 README）。代码必须同时兼容 Py3.10 与 Py3.12。

## 3. 运行时依赖与工程边界

- 运行时不 import SuperInference 的任何模块。
- worker 看门狗、硬件配置校验和从臂端点实现在 `act_deploy/hw/follower/`，模块职责见 `docs/vendored.md`。
- 修改范围限于本工程目录。
- i2rt SDK 通过设备环境中的 `.pth` 安装，由设备环境提供。

## 4. 代码结构约定

```text
act_deploy/
  model/      契约解析（ModelSpec）、观测构造、动作解码 —— 纯 numpy，两端共用
  server/     模型服务（只在模型环境运行，唯一 import torch/lerobot 的地方）
  control/    状态历史、动作调度、安全过滤、平滑轨迹 —— 纯 numpy
  hw/         机械臂（worker 进程 + RPC）、相机；均有无硬件替身
  app/        引擎状态机、控制台界面、入口
  tools/      环境自检、救援、离线自测
```

| 规则 | 说明 |
|---|---|
| 模型相关逻辑集中 | 输入怎么拼、输出怎么还原，只在 `act_deploy/model/` 里；换模型优先改配置/契约，其次改这一层 |
| 维度不写死 | 用 14 维机器人状态 `[左6关节, 左夹爪, 右6关节, 右夹爪]` 作为统一坐标；模型输出通过"目标下标"映射进来，未被控制的维度保持 |
| 单一控制线程 | 所有给机械臂的指令只从 100 Hz 控制循环发出；其他线程（按键、推理、界面）只投递请求 |
| 配置严格 | 未知键 / 缺键 / 越界值直接报错，不静默回退 |
| 注释与文档 | 代码注释英文或中文均可，面向用户的界面与文档用中文 |

## 5. 开发流程

- **不频繁测试**：一个板块开发完再统一验收（离线自测 `python -m act_deploy.tools.selftest` + sim 模式跑通）。
- 每完成一个板块，更新 `changelog.md`：列表 / 流程图优先，少堆文字；遇到具身智能概念要**通俗解释**。
- 修改硬件层模块职责或运行行为时，同步更新 `docs/vendored.md`。
- 真机相关结论只能写"待真机验证"，不能把离线通过写成真机通过。

## 6. 安全底线

1. 任何异常（推理失败、相机过期、状态过期、worker 故障）→ 立即**原地保持**，等待操作者决定，绝不自动做大幅运动。
2. 断电（释放）前必须先平滑回到零位。
3. 平滑轨迹有速度、加速度上限，以及跟随误差检查。
4. worker 进程不随主程序一起死：主程序崩溃时手臂保持通电原地不动，由 `start.sh` 自动调用救援脚本回零后再断电。
