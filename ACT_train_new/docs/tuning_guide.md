# 调参指南

## 默认值是起点

| 参数 | 默认 | 调整建议 |
|---|---|---|
| use_velocity | true（state21） | 与false做同split对照，不能直接加载另一种输入维度的权重 |
| lr / backbone_lr | 1e-5 / 1e-5 | 保留服务器默认；学习很慢时先试policy 3e-5，再试1e-4，骨干可保持1e-5 |
| dropout | 0.05 | train-prior好但val-prior变差，可试0.1；不能仅看posterior训练loss |
| 每卡batch | 16 | 显存不足先减小；总batch=每卡batch×卡数 |
| steps | 10000 | 观察验证曲线后决定；不把更多步当作必然更好 |
| checkpoint间隔 | 1000 | 小数据可更短，先考虑权重和评测开销 |
| StepLR | 两组关闭 | 验证进入平台期再对照启用，gamma先试0.5，间隔先试2000步 |
| val_stride | 16 | 越小验证越密，也越慢；最终评测仍逐帧，不用这个值抽样 |
| workers_per_gpu | 2 | 共享存储繁忙时不要盲目增加到几十个 |
| keep_top_k | 0（全部） | 需要省最终空间用2，实际保留top2+final；峰值空间仍需全部保存点 |

建议一次只改一个因素，使用同一数据集与seed；至少比较val-prior、前4步误差和逐关节曲线。报告中夹爪F1只描述阈值状态分类，不是抓取成功率。

## 不同规模的数据

不根据episode数量自动缩放lr，因为时长、动作多样性和重复程度同样重要。可以用合法chunk数估计样本预算：

`等效遍历次数 ≈ steps × gpus × batch_size_per_gpu / train_valid_chunks`

例如10000个合法窗口、总batch32、10000步约为32次遍历。增加GPU而不减steps会增加总样本预算；即使预算相同，大batch的优化过程也不保证等价。

小数据优先增进演示覆盖、固定验证集、较短训练配合best选择。数据较多则关注GPU利用率与读取瓶颈，逐渐增加batch或workers。只为现有硬件测量，不承诺4卡线性加速。

## 排查顺序

1. loss非有限或第一步异常：先检查数据单位、图像颜色、action偏移和归一化。
2. 相对动作还原整体偏移：核对是否用同一个当前follower作为整个chunk基准。
3. 速度版表现反常：检查前两帧补零、100ms历史、episode边界，不能换成未来差分。
4. 夹爪指标漂亮但动作失败：看开/闭类别比例与混淆矩阵，别只看阈值一致率。
5. 前4步好、长窗口差：结合部署只执行4步的实际协议评估，不能直接把整块按更高频率发给机器人。
