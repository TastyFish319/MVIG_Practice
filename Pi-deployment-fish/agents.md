# Pi-deployment-fish 开发约定

本文件适用于本工程及其子目录；后续开发先阅读本文件。用户在对话中的明确指令优先。

## 目标与边界

- 在与 I2RT YAM 双臂直接连接的 Ubuntu 主机上，使用 RTX 5090 本地运行 π0.5 推理并控制 follower。
- 工程必须独立：从 `ACT_deployment_new` 和 `Pi-train-new` 复制必要源码到本工程；运行时不得依赖它们的源码路径或 import 它们的包。环境中的 i2rt、LeRobot 等第三方库可以继续使用。
- 结构参照 ACT：`pi_deploy/{model,server,control,hw,app,tools}`、`configs/`、`checkpoints/`、`docs/`、`tests/`、`logs/`、根目录 `start.sh`。
- 不修改两个参考仓库，不擅自提交 git，不下载大权重或启动训练。

## 主机与环境

| 位置 | 约定 |
|---|---|
| Windows 本地 | 开发、无硬件验收；所有工程文件写在本目录 |
| `mvig-training` | 用户已授权读取 runs 中的训练记录及部署所需元数据；不修改服务器产物 |
| `mvig-ubuntu` | 用户明确通知可连接前，不尝试 SSH、探测或控制硬件 |

- 优先复用 Ubuntu 原设备 Python 环境，保留设备/推理两个进程，避免新模型依赖影响机器人 SDK。
- Pi 模型环境按训练使用的 LeRobot 版本配置；是否可复用 ACT 模型环境须先核对依赖，不能直接假定兼容。
- 新依赖写入 `requirements.txt` 与中文安装指南；普通 PyPI 包优先使用 `https://pypi.mirrors.ustc.edu.cn/simple`，CUDA 专用 wheel 等例外说明原因。
- 设备端兼容 Python 3.10，模型端按训练环境配置。所有解释器、SDK、tokenizer 路径可配置。

## 数据契约

- checkpoint 中 `pitrain_contract.json`、模型 config、处理器及其统计量是解释输入输出的依据；不能从维数猜测语义。
- 统一机器人坐标使用 `[左6关节, 左夹爪, 右6关节, 右夹爪]`；Pi 输入按契约 `state_names` 重排，默认右臂在前。输出按 `action_names` 映射回统一坐标。
- 关节训练目标是相对量，同一动作块共用观测时刻的 follower 状态作基准；夹爪是绝对值。复用 Pi05Runner 时，其输出已经还原为绝对目标并完成夹爪软下限滤波，禁止再次加状态。
- 保留训练时的 RGB、letterbox、图像尺寸、相机次序、文本 prompt、归一化和可选速度定义。
- 训练的随机图像增强不用于推理；推理使用确定性的预处理。
- 一键启动提供夹爪软下限滤波选择 `checkpoint/on/off`（沿用权重配置/启用/关闭）；关闭只禁用软下限，仍裁剪夹爪至 [0,1]。选择与最终生效参数必须显示并记录。
- 可选速度必须复现训练计算与开局 padding；无速度模型不得强行增加输入维数。
- 未来输入输出变化集中在 `model/` 和配置层，避免散落到控制与硬件层。

## 执行与交互

- 任务注册表映射任务、权重目录、prompt（默认来自契约）、时长上限；选择任务后递归发现完整 checkpoint，不能只加载裸权重。
- 所有任务执行前都平滑到各自 tasks.yaml 的 start_pose；blue_block 保留 ACT 初始姿态，另三个任务按用户要求使用原始 episode_0000 首帧 follower 状态（来源见 docs/vendored.md）。零位、相机序列号、CAN 映射以 ACT 源码核对结果为准并记录来源。
- 启动菜单：选任务 → 选权重 → 选模式 → 状态面板。保留模拟、影子、真机模式，并明确影子模式是否会移动到初始姿态。
- 支持 Enter 分步启动、空格急停保持、z 平滑回零、f 结束本次任务、r 回零后释放；界面用中文说明当前状态、下一步、异常。
- 普通结束、人工判定失败或任务时限到达：平滑回零并保持通电等待下一步。模型本身不默认具备任务成功检测能力。
- 软件急停、相机/状态失效、跟随异常、通信失效：优先停止策略并保持；异常仍存在时禁止自动运动或自动断电。恢复条件满足后由操作者 z 回零。软件急停不能替代物理急停。
- 单一控制循环负责向机械臂发目标，推理线程与按键线程只提交数据/请求。保留 worker 看门狗与崩溃救援。
- 模型启动预热与真实观测预热必须丢弃输出；完成后才允许策略执行。统计首轮/稳态时延、动作覆盖时长，拒绝过期结果；推理耗时不能阻塞控制心跳。

## 开发、记录与验收

- 文档、界面面向具身智能初学者：用数据流、例子、短列表解释，不堆术语。
- 开始时建立 `changelog.md`；每完成一个板块或出现重要发现就更新，记录变更、原因、验收结果与待办。
- 按模块集中验收，不每做一个小改动就运行测试；重点验证契约/维度映射、速度 padding、时序、急停/回零/释放、故障和模拟全链路。
- 复制清单、来源路径、后续改动写入 `docs/vendored.md`；新增配置必须严格校验，不静默猜测或吞掉错误。
- 严格区分：静态检查通过、离线模拟通过、真实 checkpoint GPU 推理通过、真机通过。未经实际运行不得声称加载/速度/真机部署成功。
- 权重、tokenizer 与真实 RTX 5090 不在本机时，完成可复现的验收工具和命令，明确剩余验证条件，不伪造结果。
