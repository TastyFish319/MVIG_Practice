# 从摄像头到机械臂运动：一步步看

## 1. 模型在看什么

左右 follower 是真正执行任务的两条机械臂。每条臂有6个关节位置和1个夹爪开合值，两条共14维；关节用弧度，夹爪0约为关闭、1约为打开。推理不需要连接 leader。

相机给两张 RGB 图。设备程序在后台保留最新帧，检查是否过期，按训练流程等比例缩放并补黑边到224×224。训练时随机改变颜色或轻微变换画面，是为了让模型适应变化；推理时关闭随机增强，让相同画面的预处理结果稳定。

每次推理把“观测时刻的左右臂位置 + 左右腕图片 + 权重内任务文字”一起送到模型。Pi 的位置顺序通常是右臂在前，而设备内部是左臂在前，因此只在模型适配层按名称重排。

## 2. 可选的速度不是一串未来信息

速度描述刚才怎么动：把过去100ms的位置样本拟合成一条直线，斜率就是速度。它只看过去。历史不足两点时先补零，并在面板标识；有两点即可估计，不会强制每轮前100ms都补零。

当前三个已核对模型都没有用速度，因此输入只有14维位置。未来速度模型的输入会是14维位置加14维速度，共28维，程序按契约选择。实际采样频率与训练原始数据略有差异，需要真机核验速度分布。

## 3. 模型返回的是什么

一次预测50步动作；训练帧率30Hz，所以相邻动作相隔约33ms，总长约1.67秒。它像是“未来一小段时间的位置计划”，不是给电机的力或力矩。

例如：观测时右肘为1.0rad，模型第10步的相对预测为+0.1rad，则这一点的绝对目标是1.1rad。**同一块的全部点都加观测时的1.0，而不是逐点累加**。夹爪本来就是绝对开合值，不加当前夹爪。

训练代码的 Pi05Runner 已完成反归一化、加回原始位置和夹爪滤波，因此设备收到的就是绝对目标。右臂模型输出7维，左臂保持；双臂模型输出14维，两条臂都映射回对应位置。

## 4. floor 开关控制哪一步

夹爪原始输出如果很小，可能意味着模型要持续夹紧。软下限使它平滑趋近训练估计的 floor，例如0.22，避免过度挤压。它不是关节限位，也不是任务完成检测。

菜单选择 off 后禁用这个软下限，输出0可以真的变成完全闭合命令；仍裁剪到合法范围0..1。启用时保留该任务权重保存的 knee/floor，不会把开罐的参数硬套到积木任务。

## 5. 为什么模型不必每10ms预测一次

GPU每次预测一整块计划，设备控制循环每10ms从当前计划按时间插值得到一个目标并发送。当前默认每约15个模型步重新规划一次；这相当于“每约0.5秒更新路线”，同时“每0.01秒更新一次机械臂目标”。

新计划可能和旧计划略有差别，调度器会短暂淡入；之后还有速度限制与目标相对实测位置的偏离限制。初始化和回零使用五次多项式曲线，使起步和停下更柔和。

```text
相机+关节观测 → Pi模型 → 50步位置计划
                        ↓
                按时间取点、插值、切换淡入
                        ↓
              限速 / 目标偏差限制 / 夹爪范围
                        ↓ 每10ms
             portal RPC → 左右worker → i2rt SDK → CAN → 电机
```

电机最终如何追踪目标，由i2rt控制接口和电机自身控制器执行。模型没有直接操纵CAN报文。worker还独立检查指令时间、租约和反馈；主程序失去心跳时进入保持。

## 6. 推理慢了会怎样

- 加载后先用合成输入预热；启动设备后再用真实观测预热。两种预热的动作都丢弃，不让机械臂照着假图片运动。
- 设备提前请求下一块；GPU计算不会堵住发送给机械臂的心跳。
- 若推理用了200ms，计划前面约6步已经过去，程序按真实时间使用后面的点，不从第0步迟到补播。
- 若整个计划到达时已过期，就丢弃。首块一直没来、连续错误或当前计划耗尽过久，立即停止策略并保持。
- 暂停/急停后每轮有新的执行代号；以前在途的结果即使稍后返回，也不能再启动机械臂。

面板会显示推理耗时、端到端延迟、反馈/图像新鲜度、预热和限幅次数；具体错误写进events.log及server.log。

## 7. 一次任务从头到尾

```text
选任务 → 选完整权重 → 选模式/执行方式/floor
  → 加载+合成预热（此时未启动机械臂）
  → 启动worker保持、相机、控制循环 → 真实观测预热
  → Enter：平滑初始化 → READY
  → Enter：执行任务 ↔ p：暂停/继续
  → f或时限到达：经初始姿态平滑回零 → ZERO等待
  → Enter：下一轮，或 r：确认零位后释放退出
```

急停/故障是另一条路径：停止采用模型目标 → 保持 → 排查并恢复 → z平滑回零。错误发生时无法保证回零路径畅通，因此不自动运动。回零未到位也不会自动断电。

软件保持意味着电机还在支撑机械臂。释放意味着电机可能失去支撑，所以必须到安全零位再释放。主程序崩溃后worker尽量保持，需显式执行 --rescue，脚本核对归属后逐侧接管；供电丢失、硬件故障或worker本身崩溃并不能由软件保证保持，仍需现场安全措施。
